# Go 编码规范

适用于所有 Go module 的手写代码，包括测试和基准测试；生成代码通过生成器或模板维护。

编写、修改或审查代码前，读取本文及 [Uber Go 规范](uber-go/style.md)的相关章节。**冲突时，本文补充规则优先**；其余遵循原文的适用条件、要求强度和例外。

## 设计与可读性

- 保持高内聚、低耦合和单一职责；新增抽象须有当前需求、明确职责和依赖方向。
- 优先级：安全 > 清晰度 > 简单 > 简短。
- 保持主流程平直，减少不必要的复杂性和嵌套。
- 按业务用途命名，沿用[领域术语](../../../GLOSSARY.md)，使用 MixedCaps 并保持一致的缩写。
- 多行结构体定义及字面量逐字段换行；简短初始化和测试表行可保持单行。
- 保留必要换行，删除冗余不必要的空行。
- 注释用简洁中文解释意图、约束或所有权。
- 仅在降低理解成本时抽取公共逻辑，允许直观重复。
- import 分组以 [.golangci.yml](../../../.golangci.yml)为准，覆盖 [Uber 的两组划分](uber-go/style.md#import-group-ordering)。

## 测试

- 用例直接呈现关键前提、执行动作和预期结果。
- 优先扩展就近的现有测试，仅补充未覆盖的行为或回归风险。新文件须有职责、构建或隔离需要。
- 测试辅助函数放在用例后，共用夹具按职责就近组织。
- 资源创建成功后立即注册清理，再断言就绪；阻塞 worker 须有失败释放路径，并有界等待退出。
