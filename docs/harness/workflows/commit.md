# 提交流程

授权与执行边界见 [AGENTS 执行约定](../../../AGENTS.md#执行约定)。

## 确定范围

- 用户指定范围时按指定范围处理。
- 未指定范围且已有暂存内容时，只提交已有暂存内容；否则纳入已确认的当前任务改动。
- 用户要求所有改动时，逐项复审全部待提交内容。
- 保留部分暂存边界。已有暂存内容与指定范围冲突时，先说明冲突并明确范围，不擅自扩大或撤销暂存。

## 执行步骤

1. 查看 `git status --short`、已暂存与未暂存差异，读取候选未跟踪文件，记录范围、分支与 HEAD。存在冲突或未完成的 Git 操作时，报告并停止提交。
2. 复审候选内容，仅用明确路径暂存已审核的改动，再用 `git write-tree` 记录候选树。只提交已有暂存内容时，保留暂存区，不按整文件重新暂存。
3. 执行 `git diff --cached --check`，按改动影响验证候选内容。工作区与暂存内容不同时，在仓库外的临时目录验证完整候选树，保留多 module 布局；工作区的验证结果不能代替候选内容的结果。
4. 每次提交一个原子改动，源文件与生成文件一起提交。格式为 `<type>(<scope>): <中文摘要>`，type 使用 `feat|fix|refactor|docs|test|chore`；必要正文说明改动原因和验证。
5. 提交前复查分支、HEAD 与暂存树，有变化先重新复审和验证，再创建新提交。正常执行 hooks 和签名；失败时保留现场并报告，不绕过检查或自动改写提交。
6. 提交后确认实际树与候选一致、父提交为记录的 HEAD，再查看剩余工作区，报告 SHA、分支、摘要、验证结果和未提交内容。提交命令超时或失败时，先确认是否已产生提交，再决定是否重试。
