# 完成前清理

以本次功能完成后的行为为基线，对任务涉及的代码做一次等价清理。先保证清晰易读，再简化结构；以降低阅读和维护成本为目标。

1. **确认范围。** 从本任务开始时的基线核对改动，包含任务内已提交的部分。修改遵循 [范围约定](../../AGENTS.md#范围)，清理对象为手写代码。

2. **阅读完整逻辑。** 逐一阅读受影响的函数、类型和测试，按需追踪直接调用关系。结合正常路径、错误分支和边界情况理解实现。

3. **明确等价约束。** 确认每项实质性调整需要保留的接口契约、返回值、错误和副作用。
   仅在确认不影响可观察行为时，才调整求值次数与顺序、`nil` 与空值的表示或引用共享方式。
   涉及并发或资源时，保持同步关系、资源所有权、释放时机与次数、取消语义和等待范围。

4. **实施有收益的清理。** 按 [Go 编码规范](go-styles.md) 和 [.golangci.yml](../../.golangci.yml) 检查命名、职责分组、嵌套、重复流程、无用代码、冗余抽象及注释。
   优先采用清楚直接的写法，保留有助于组织代码的抽象。连续逻辑与空行按语义组织，复杂表达式按阅读需要展开。

5. **逐项核对行为。** 对照每项调整前后的实现，结合调用方和测试确认等价性。无法确认的调整保留原实现，并说明具体原因。
   发现缺陷时，行为修正与等价清理分开说明，并按以下范围处理：

   - 本次任务引入或属于已授权修复范围的缺陷，在预期行为明确时直接修复，并补充必要的回归验证。
   - 范围外的既有缺陷，仅报告位置、触发条件、证据和影响。
   - 修复涉及的预期行为或接口契约不明确时，先报告疑点并确认，再实施修复。

6. **验证并完成复核。** 按 [完成条件](../../AGENTS.md#完成条件) 验证清理后的最终版本。优先使用现有测试，针对缺失的行为证据补充必要用例。
   确认范围内的代码均已检查，简述实质性改动和验证结果；没有合适的改动时，说明已检查即可。
