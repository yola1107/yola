# Go 编码规范

编写或审查手写 Go 代码时遵循本文；自动检查与格式工具配置以 [.golangci.yml](../../.golangci.yml) 为准。

## 设计与命名

- 命名体现职责，避免含糊的 `utils`、`common` 包。优先使用标准库、已有依赖和具体类型，按实际需求抽象。
- 接口由使用方按需定义，依赖通过构造函数注入。
- 函数职责单一，先处理错误和边界情况。长调用与复杂条件按语义拆分，保持原有求值顺序。
- 结构体字段按职责分组，相关函数和方法集中放置，便于连贯阅读。
- 重复流程的职责和失败处理一致时，可提取复用；抽取后保持资源释放顺序，调用处应能看清主要步骤。
- 结合上下文和作用域简洁命名，省去已明确的信息，保留角色、状态、单位等必要区别。
  例如：上下文明确时可用 `i`、`j`、`k`、`v`、`opt`；需要区分角色时用 `sourceAccount`、`targetAccount`。
- 函数名表达操作，处理对象可由名称、包名或接收者明确，如 `renderAward`、`encodeBoard`；名称不堆叠执行步骤或测试断言。

## 语句与排版

- 空行按语义和阅读节奏分组。调用、错误处理与结果使用尽量保持连贯；切换处理阶段时可留一行，不按语句类型或固定行数机械分隔。
- 每行只写一条执行语句。函数、匿名函数和回调含多条语句或嵌套代码块时，函数体展开为多行。
- 单行函数体仅用于单条简单的返回、赋值或调用。`if`、`switch` 初始化语句和三段式 `for` 头部保留惯用的分号写法。
- 单条语句也按信息量排版。字段或参数较多、表达式较长时，按字段或参数展开，便于逐项阅读；短小清晰的字面量和调用可保留单行。

```go
func (b *backend) close() {
	b.once.Do(func() {
		close(b.done)
		_ = b.conn.Close()
	})
}
```

## 错误、Context 与并发

- 检查并处理错误；补充背景时用 `%w`，判断错误用 `errors.Is/As`。
  错误在负责处理的边界记录一次，预期业务失败返回 `error`，不用 `panic`。
- 需要 Context 时，以 `ctx context.Context` 为首参数并沿调用链传递，不存入结构体或切断请求链。
  创建可取消的 Context 后，负责调用 `cancel`。
- 明确资源的释放责任，以及 goroutine 的退出、取消和等待方式。批量并发设置上限，共享可变状态正确同步。
  同一所有者负责的任务，退出条件和等待边界一致时，可统一取消、等待和清理。

## 测试

- 测试可观察行为，覆盖正常、边界和失败场景；修复缺陷补回归用例。
- 测试之间保持独立，隔离资源后再并行。

## 注释

- 手写包及导出 API 补充文档注释，分别以 `Package <包名>` 和符号名开头。说明用途、约束和错误，不复述代码。

## 生成代码

- 生成文件保留工具写入的 `Code generated … DO NOT EDIT.` 标记，只通过重新生成更新。
- 只为真实生成文件使用生成标记；手写代码、测试和 schema 继续参与检查。
