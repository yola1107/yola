# Go 编码规范

本文维护 Go 编码约定，适用于手写业务代码和测试代码。

格式与静态规则以 [.golangci.yml](../../.golangci.yml) 为准。

## 命名与结构

- 命名简短且表意，沿用领域用词。省去上下文已有信息，保留必要区别。使用 MixedCaps 和 `ID`、`HTTP`、`RTP` 等惯用缩写，不生造缩写。
- 改名须同步受影响的引用，不为缩短名称批量改名。
- 包级未导出变量和常量（含哨兵错误）不强制加 `_` 前缀。
- 优先标准库和具体类型。保留有助理解和组织代码的抽象，新增抽象须降低当前复杂度。
- 先处理错误和边界，用提前返回或 `continue` 减少嵌套。只抽取有独立职责的步骤，保持主流程直接。
- 同一文件内按大致调用顺序排列函数。主流程在前，被调用的函数在后。导出函数优先，同一接收者的方法集中排列，通用辅助函数放在文件后部。
- 同一类型的方法统一接收者名称和形式。有方法需要修改接收者、类型含锁或复制成本较高时，统一使用指针接收者。可安全复制的小值类型可统一使用值接收者。调整已有方法时核对接口依赖的方法集。
- 结构体声明展开为多行，每行单独声明一个字段。空结构体保留 `struct{}`，简短初始化允许单行。
- 函数签名优先单行，过长影响可读性时再换行。
- 必需依赖显式传入。参数容易混淆时使用请求结构体。
- 简化或重构保持行为不变。保留随机调用次数与顺序、金额精度、错误匹配、`nil`/空集合语义、锁范围及 I/O 时序。
- 未要求变更的协议字段、编号、JSON 标签和冻结样本保持原值。

## 校验与错误

- 外部输入在边界校验；内部复用已建立的不变量。金额、权限和并发状态按业务契约检查。
- 错误须处理或向上传递。需保留错误身份时用 `%w` 包装，以 `errors.Is/As` 判断。脱敏须保留取消、超时和提交未知语义。
- 提交、写入及影响完整性的清理错误必须处理。可安全忽略的清理错误显式写 `_ =`。
- 日志按需在处理边界记录一次，不输出凭据、完整敏感请求或私有玩家资料。业务核心通过返回值或业务接口提供事实，日志与 tracing 放在边界和运行层。

## Context、并发与资源

- Context 以首参数 `ctx context.Context` 沿调用链传递。创建方负责确保取消函数被调用。显式返回或转交取消责任时，由接收方调用。
- 后台任务由生命周期所有者管理，批量并发设置上限，收尾设超时。
- 需在请求取消后完成的清理使用 `context.WithoutCancel(ctx)` 并设置超时，保留 trace 等上下文值。
- 资源在失败与退出路径都要释放。停止顺序为停止接入、取消并等待任务、关闭依赖。
- 共享数据明确修改权与同步责任，保持锁序及跨实例协调契约。网络调用避免长期占用业务锁。

## 注释与生成

- 中文注释说明契约、原因、单位或所有权。导出类型、构造函数和跨包入口说明职责或契约，注释以声明名开头。
- 自解释字段、简单构造函数和访问器无需重复注释。资源所有权与清理责任、失败行为和生命周期约定仍须说明。普通 package/import 无需注释。
- 生成代码只改输入并重新生成，保留生成标记。
- 静态检查发现问题时先修代码。新增 `nolint` 等检查豁免须经用户明确同意，并注明具体检查项和原因。
